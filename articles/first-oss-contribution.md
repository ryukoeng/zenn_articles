## 「無いなら自分が作ればいい」と思った

先日、生まれて初めて OSS に貢献した。プルリクエストがマージされたときは、思っていた以上に嬉しかった。今日はその話を書きたい。

きっかけは、いつも通り仕事の中にあった。[Floci](https://github.com/floci-io/floci-ui) というローカル向けのクラウドコンソールを触っていて、AWS の Secrets Manager にあたる画面を使いたくなった。ところが、その機能がまだ無かった。

最初は「無いのか、残念」で終わるところだった。でも少し考えて、ふと思った。無いなら、自分が追加すればいいのではないか。使う側として「欲しい」と思った機能を、自分の手で足せる。それが OSS なんだと、頭ではわかっていたつもりだったけれど、初めて自分ごととして実感した瞬間だった。

---

## 作ったもの

追加したのは AWS Secrets Manager の画面一式だった。シークレットの一覧を出して、メタデータやタグを見て、値を表示したりコピーしたり編集したり、新しく作ったり消したりできる。バックエンドは既存のサービスに倣って Hono で API を書いて、AWS SDK の Secrets Manager クライアントを包む形にした。

機能を足すだけなら気楽だが、扱うのが「シークレット」だったので、そこは慎重にやった。値はリクエストされるまで隠しておく、表示した値はキャッシュに残さない、入力が欠けていたら AWS の 500 をそのまま出さずに 400 で返す。地味だけれど、こういう配慮の積み重ねがレビューを通すうえでも効いてくる。最終的にはユニットテストも含めて、それなりの量のコードになった。

「自分が欲しい」から始まった機能が、形になっていくのは純粋に楽しかった。

---

## 海外のエンジニアと、初めて

提出してから一番新鮮だったのは、レビューのやりとりだった。これまで自分のコードを見てくれるのは社内の人だけだったのに、今回は会ったこともない海外のエンジニアが、自分の書いたものに目を通してコメントをくれる。

「コンフリクトを解消してくれる?」と言われて直し、別のメンバーが足りていなかったナビゲーションの組み込みを自分の PR に直接 push してくれて、こちらでも動作を確認して返す。設計方針との細かいズレについては「ここは別の PR でやってもいいですか?」と相談して、「それでいこう」と合意してマージにたどり着いた。

文字で書くと淡々としているが、知らない国の誰かと、一つのコードを挟んで会話が成立していくのは、ちょっと感動的だった。最後に付いた小さなリアクション一つでも、妙に嬉しかった。

---

## 英語は、AIと一緒に

正直に言うと、英語はあまり得意ではない。レビューへの返信も、PR の説明文も、自分一人だったらきっと尻込みしていたと思う。

そこは AI に頼った。言いたいことを日本語で整理して、英語にしてもらい、ニュアンスがおかしくないか確認しながら返す。完璧な英語を一人でひねり出すことが目的ではなくて、相手にちゃんと意図が伝わって、やりとりが前に進めばいい。そう割り切ったら、言葉の壁はずいぶん低くなった。

AI に疲れて本を読み始めた、なんて話を前に書いたけれど、こういう場面では素直にありがたい。要は付き合い方なんだと思う。

---

## やってみてわかったこと

終わってみて残ったのは、「OSS への貢献って、楽しい」というシンプルな感想だった。

自分が困ったことが出発点で、直したものが世界のどこかで他の誰かの役に立つかもしれない。レビューを通じて知らないエンジニアと関われて、英語が拙くても道具を使えば前に進める。最初の一歩は思っていたより重くなかった。

一度やってみると、次のハードルはぐっと下がる。次はもっと気軽に、小さな修正からでも手を出していきたい。

---

## まとめ

- 「使いたい機能が無い」は、OSS では貢献のきっかけになる
- 自分が欲しかった機能を自分の手で足せるのは、純粋に楽しい
- 海外のエンジニアと一つのコードを挟んで会話できるのは新鮮で、最後の小さなリアクションも嬉しい
- 英語が拙くても、AI を相棒にすれば言葉の壁は越えられる
- 最初の一歩さえ踏み出せば、次の貢献はぐっと身近になる
