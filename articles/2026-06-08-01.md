## 🖥️ EC2 とは

**Amazon EC2（Elastic Compute Cloud）** は、AWS 上で仮想サーバー（インスタンス）を必要なときに必要なだけ立ち上げられるコンピューティングサービス。

- 物理サーバーを買わずに、**数分でサーバーを起動・破棄**できる。
- CPU・メモリ・ストレージ・ネットワークを**用途に合わせて選択**できる。
- 名前の「Elastic（弾力的）」が示す通り、台数やスペックは後から増減できる。

---

## 🧩 主要な構成要素

EC2 は単体ではなく、いくつかの要素を組み合わせて使う。まず全体像を把握する。

| 要素 | 役割 | ひとこと |
| ---- | ---- | -------- |
| **インスタンス** | 起動した仮想サーバー本体 | EC2 で動く「サーバー」そのもの |
| **AMI** | インスタンスの起動テンプレート（OS＋初期構成） | 「どの状態から起動するか」の設計図 |
| **インスタンスタイプ** | CPU/メモリ等のスペック区分 | `t3.micro` のような型番 |
| **EBS** | インスタンスにアタッチする永続ストレージ | 仮想的な「外付けディスク」 |
| **キーペア** | SSH 接続のための公開鍵/秘密鍵 | サーバーの「鍵」 |
| **セキュリティグループ** | インスタンス単位の仮想ファイアウォール | 通信の許可ルール |
| **VPC / サブネット** | インスタンスを置くネットワーク空間 | サーバーの「住所」 |
| **Elastic IP** | 固定のパブリック IP アドレス | 再起動しても変わらない IP |

---

## 📦 AMI（Amazon マシンイメージ）

**AMI** は、インスタンスを起動するときのテンプレート（OS とソフトウェアの初期状態のスナップショット）。

| 種類 | 内容 | 用途 |
| ---- | ---- | ---- |
| **AWS 提供** | Amazon Linux / Ubuntu / Windows など公式 OS イメージ | 基本はこれを選ぶ |
| **マーケットプレイス** | ベンダー製のアプリ込みイメージ | ミドルウェア入りを使いたいとき |
| **カスタム（自作）** | 既存インスタンスから作成したイメージ | 構成を複製・横展開したいとき |

- 同じ AMI から起動すれば、**同一構成のインスタンスを何台でも再現**できる。
- 環境構築済みのインスタンスを **自作 AMI 化**しておくと、スケールアウトや復旧が速い。

## ⚙️ インスタンスタイプ

スペックの区分。型番は **`<ファミリー><世代>.<サイズ>`** の形で読む。

例：`t3.micro` → **t** ファミリー / 第 **3** 世代 / **micro** サイズ

| ファミリー | 特徴 | 代表的な用途 |
| ---------- | ---- | ------------ |
| **T 系**（t3, t4g） | バースト可能・低コスト | 開発環境、小規模 Web |
| **M 系**（m5, m6i） | CPU とメモリのバランス型 | 汎用サーバー全般 |
| **C 系**（c5, c6g） | CPU 最適化（計算重視） | バッチ処理、ゲームサーバー |
| **R 系**（r5, r6i） | メモリ最適化 | DB、インメモリキャッシュ |
| **G / P 系** | GPU 搭載 | 機械学習、画像処理 |

- 末尾の **`g`**（例: `t4g`）は **AWS Graviton（Arm 系 CPU）**。コスパが良いことが多い。
- 迷ったら **T 系か M 系**から始め、負荷を見て調整するのが定石。

## 💾 ストレージ（EBS とインスタンスストア）

EC2 のストレージは大きく 2 種類。両者の違いは**永続性**にある。

| 種類 | 永続性 | 特徴 |
| ---- | ------ | ---- |
| **EBS** | ✅ 永続（インスタンス停止・削除後も残せる） | ネットワーク接続型のブロックストレージ。スナップショット取得可。基本これ |
| **インスタンスストア** | ❌ 揮発（停止・終了で消える） | 物理ホスト直結で高速だが一時的。キャッシュ等の用途のみ |

EBS のボリュームタイプも用途で使い分ける。

| タイプ | 概要 | おすすめ度 |
| ------ | ---- | ---------- |
| **gp3 / gp2** | 汎用 SSD。コストと性能のバランス | ✅ 推奨 |
| **io2 / io1** | 高 IOPS のプロビジョンド SSD | DB など高性能が必要なとき |
| **st1 / sc1** | HDD ベース。大容量・低コスト | ログ保管やアーカイブ |

- 通常は **gp3** を選んでおけば間違いない。
- **スナップショット**を取ると S3 にバックアップされ、別 AZ への復元や AMI 化に使える。

## 🌐 ネットワーク（VPC・サブネット・IP）

インスタンスは必ず **VPC（仮想ネットワーク）内のサブネット**に配置される。

| 用語 | 説明 |
| ---- | ---- |
| **VPC** | AWS 上に作る論理的なネットワーク空間 |
| **サブネット** | VPC を区切ったネットワーク。AZ ごとに作る |
| **パブリックサブネット** | インターネットゲートウェイ経由で外部疎通できるサブネット |
| **プライベートサブネット** | 直接の外部疎通を持たない（DB などを配置） |
| **ENI** | インスタンスに付く仮想ネットワークインターフェース |

IP アドレスの扱いは混同しやすいので整理する。

| 種類 | 特徴 |
| ---- | ---- |
| **プライベート IP** | VPC 内での通信用。インスタンスに必ず割り当てられる |
| **パブリック IP** | 自動付与だが、**停止・起動で変わる**（固定されない） |
| **Elastic IP** | **固定**のパブリック IP。再起動しても不変。明示的に割り当てる |

- IP を固定したいなら **Elastic IP** を割り当てる。
- ただし**未使用の Elastic IP には課金**されるので、使わなくなったら解放する。

## 🔑 キーペア

SSH（Linux）や RDP（Windows）でインスタンスに接続するための**公開鍵認証の鍵**。

- インスタンスに**公開鍵**が登録され、手元で**秘密鍵（`.pem`）**を使って接続する。
- 秘密鍵は**作成時に一度しかダウンロードできない**ため厳重に保管する。
- 紛失するとそのインスタンスには鍵での再接続ができない（別途復旧手順が必要）。

```bash
# Linux インスタンスへの接続例
ssh -i my-key.pem ec2-user@<パブリックIP または Elastic IP>
```

## 🛡️ セキュリティグループ

**インスタンス単位の仮想ファイアウォール**。許可するトラフィックをルールで定義する。

| 項目 | 説明 |
| ---- | ---- |
| **インバウンド** | インスタンスへ**入る**通信の許可ルール |
| **アウトバウンド** | インスタンスから**出る**通信の許可ルール |
| **ステートフル** | 許可した通信の戻りは自動で許可される |

| よくあるルール | ポート | 用途 |
| -------------- | ------ | ---- |
| SSH | 22 | Linux への接続 |
| RDP | 3389 | Windows への接続 |
| HTTP | 80 | Web 公開 |
| HTTPS | 443 | Web 公開（暗号化） |

- **SSH（22）を `0.0.0.0/0`（全開放）にしない**。自分の IP に絞るか、踏み台・SSM 経由にする。
- 「拒否」は書けず、**許可ルールだけを足していく**ホワイトリスト方式。

## 💰 料金モデル

同じインスタンスでも**買い方**でコストが大きく変わる。

| 購入方式 | 概要 | 向いているケース |
| -------- | ---- | ---------------- |
| **オンデマンド** | 秒/時間単位の従量課金。契約不要 | 短期・検証・変動が読めない負荷 |
| **スポット** | 余剰リソースを最大 90% 割引で利用。中断あり | 中断耐性のあるバッチ・並列処理 |
| **リザーブド（RI）** | 1〜3 年の利用を予約して割引 | 稼働が読める定常的なサーバー |
| **Savings Plans** | 一定の利用量をコミットして割引 | 柔軟に割引を受けたい長期利用 |

- 検証・学習中は **オンデマンド** で十分。
- 常時稼働が決まったら **Savings Plans / RI** でコスト最適化を検討する。
- 停止中のインスタンスに **EC2 料金**はかからないが、**EBS や Elastic IP には課金**される点に注意。

---

## 🔄 インスタンスの状態（ライフサイクル）

| 状態 | 意味 | 課金 |
| ---- | ---- | ---- |
| **pending** | 起動処理中 | なし |
| **running** | 稼働中 | ✅ EC2 課金あり |
| **stopping / stopped** | 停止中／停止済み | EC2 は無課金。EBS は課金継続 |
| **terminated** | 完全に削除済み（復元不可） | なし |

- **停止（stop）** は一時的にサーバーを止めるだけで、EBS のデータは残る。
- **終了（terminate）** はインスタンスを破棄する。デフォルトでは EBS も削除されることが多いので注意。

---

## 🧠 まとめ

- EC2 は **数分で立てて壊せる仮想サーバー**。スペックも台数も後から変えられる。
- 起動には **AMI（テンプレート）＋インスタンスタイプ（スペック）＋EBS（ストレージ）** の組み合わせが基本。
- ネットワークは **VPC / サブネット** に置き、**セキュリティグループ**で通信を絞る。IP を固定したいなら **Elastic IP**。
- 接続は **キーペア**。秘密鍵は一度しか落とせないので大切に。
- 料金は **買い方しだい**。停止中でも **EBS・Elastic IP には課金**される点を忘れない。
