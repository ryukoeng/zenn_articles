## IPアドレスとは

**IPアドレス** は、ネットワーク上の機器を識別するための**住所**にあたる番号。

- 現在広く使われている **IPv4** は、`192.168.1.10` のように **8 ビット × 4 つ（計 32 ビット）** で表す。
- 各区切り（オクテット）は **0〜255** の範囲を取る。
- このアドレスは「**どのネットワークか（ネットワーク部）**」と「**その中のどの機器か（ホスト部）**」の 2 つの情報を 1 つにまとめたもの。

この記事では、VPC やサブネット設計の土台になる **ネットワーク部・ホスト部・ネットマスク** の関係を整理する。

---

## IPアドレスの構造（ネットワーク部とホスト部）

IPアドレスは、前半の **ネットワーク部** と後半の **ホスト部** に分かれる。

| 部分               | 役割                           | 住所でいうと     |
| ------------------ | ------------------------------ | ---------------- |
| **ネットワーク部** | どのネットワークに属するか     | 「〇〇町××丁目」 |
| **ホスト部**       | そのネットワーク内のどの機器か | 「△番地」        |

- **同じネットワーク部**を持つ機器同士は、ルーターを介さず直接通信できる。
- どこまでがネットワーク部で、どこからがホスト部かを決めるのが、次の **ネットマスク**。

---

## ネットマスク（サブネットマスク）

**ネットマスク** は、IPアドレスのうち**どこまでがネットワーク部か**を示す目印。

- ネットワーク部にあたるビットを **1**、ホスト部にあたるビットを **0** で表す。
- 例：`255.255.255.0` を 2 進数にすると `11111111.11111111.11111111.00000000`。
  - **先頭 24 ビットが 1（ネットワーク部）／残り 8 ビットが 0（ホスト部）**。

| ネットマスク    | 2 進数                                | ネットワーク部のビット数 |
| --------------- | ------------------------------------- | ------------------------ |
| `255.0.0.0`     | `11111111.00000000.00000000.00000000` | 8 ビット                 |
| `255.255.0.0`   | `11111111.11111111.00000000.00000000` | 16 ビット                |
| `255.255.255.0` | `11111111.11111111.11111111.00000000` | 24 ビット                |

- IPアドレスとネットマスクを **AND 演算**すると、そのネットワークの**ネットワークアドレス**が求まる。

---

## ネットワークアドレスとホストアドレス

ネットマスクで区切ると、ネットワーク内のアドレスは次のように役割が決まる。

| 種類                         | 内容                                           | 例（`192.168.1.0/24` の場合）    |
| ---------------------------- | ---------------------------------------------- | -------------------------------- |
| **ネットワークアドレス**     | ホスト部が**すべて 0**。ネットワーク自体を表す | `192.168.1.0`                    |
| **ホストアドレス**           | 機器に実際に割り当てられる範囲                 | `192.168.1.1` 〜 `192.168.1.254` |
| **ブロードキャストアドレス** | ホスト部が**すべて 1**。全機器宛て             | `192.168.1.255`                  |

- **ネットワークアドレス**と**ブロードキャストアドレス**は機器に割り当てられない（予約）。
- したがって、実際に使える **ホストアドレス**は「全体 − 2」になる。

---

## ブロードキャストアドレス

**ブロードキャストアドレス** は、そのネットワーク内の**全機器に一斉送信**するための特別なアドレス。

- ホスト部のビットを**すべて 1** にしたもの。
- `192.168.1.0/24` なら `192.168.1.255`。
- 個々の機器には割り当てられないため、ホストアドレスの計算から除外する。

---

## CIDR 表記

ネットマスクを毎回 `255.255.255.0` と書くのは冗長なので、**CIDR 表記**で「ネットワーク部のビット数」を `/24` のように書く。

| CIDR  | ネットマスク      | ネットワーク部 | ひとこと         |
| ----- | ----------------- | -------------- | ---------------- |
| `/8`  | `255.0.0.0`       | 8 ビット       | とても広い       |
| `/16` | `255.255.0.0`     | 16 ビット      | 広い             |
| `/24` | `255.255.255.0`   | 24 ビット      | 手頃な単位       |
| `/28` | `255.255.255.240` | 28 ビット      | 小さなサブネット |

- **数字が小さいほどネットワーク部が短く、ホスト部が長い ＝ 広い範囲**。
- `192.168.1.0/24` は「`192.168.1.0` というネットワークで、ネットマスクは `/24`」という意味。

---

## 使えるホスト数の計算

ホスト部のビット数を **n** とすると、使えるホストアドレスの数は次の式で求まる。

```
使えるホスト数 = 2のn乗 − 2
```

`−2` は **ネットワークアドレス**と**ブロードキャストアドレス**の分。

| CIDR  | ホスト部のビット数 | 全アドレス数（2のn乗） | 使えるホスト数（−2） |
| ----- | ------------------ | ---------------------- | -------------------- |
| `/24` | 8                  | 256                    | **254**              |
| `/25` | 7                  | 128                    | **126**              |
| `/26` | 6                  | 64                     | **62**               |
| `/28` | 4                  | 16                     | **14**               |
| `/30` | 2                  | 4                      | **2**                |

- `/30` は使えるホストが 2 つだけ。ルーター同士の**点対点接続**などに使う。
- なお **AWS のサブネット**では、各サブネットで先頭 4 つ＋末尾 1 つの **計 5 つを AWS が予約**するため、上記からさらに引いた数になる。

---

## プライベート IP アドレス

インターネットに直接出ない**社内・VPC 内専用**のアドレス帯が、RFC で予約されている。

| クラス   | プライベート IP の範囲             | CIDR             |
| -------- | ---------------------------------- | ---------------- |
| クラス A | `10.0.0.0` 〜 `10.255.255.255`     | `10.0.0.0/8`     |
| クラス B | `172.16.0.0` 〜 `172.31.255.255`   | `172.16.0.0/12`  |
| クラス C | `192.168.0.0` 〜 `192.168.255.255` | `192.168.0.0/16` |

- VPC やオンプレの社内ネットワークには、この**プライベート IP の範囲**から CIDR を選ぶのが基本。
- 別ネットワークと接続する可能性を考え、**範囲の重複を避けて**設計する。

---

## まとめ

- IPアドレスは **ネットワーク部 ＋ ホスト部** の組み合わせで、その境界を決めるのが **ネットマスク**。
- ホスト部が**すべて 0** が **ネットワークアドレス**、**すべて 1** が **ブロードキャストアドレス**。この 2 つは予約され機器に割り当てられない。
- **CIDR 表記（`/24` など）** はネットワーク部のビット数を表し、**数字が小さいほど広い**。
- 使えるホスト数は **`2のn乗 − 2`**（n はホスト部のビット数）。AWS ではさらに 5 つ予約される。
- VPC 設計では、これらを踏まえて **プライベート IP の範囲から重複しない CIDR を選ぶ**ことが土台になる。
